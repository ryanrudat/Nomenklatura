# Session 026 - Game Design Audit & Bureau Directive Target Selection Fix

**Date:** 2026-04-13

## Summary

Comprehensive game design audit followed by critical bug fixes and UX improvement implementation. Identified that 3 of 6 bureau directive execution paths were broken (passing `nil` for all required targets), making diplomatic, military, and state ministry directives non-functional from the Directive Phase. Also added a crisis-aware urgency triage system to help the General Secretary prioritize actions during crises.

## Game Design Audit Findings

### Context
- Player starts at Position 8 (General Secretary) — game is about **keeping** power, not climbing
- 207 total defined actions across 14 categories
- Player gets 3 AP + 2 directive points per turn (5 actions from 207 options)
- 5 navigation tabs + 3 header buttons = 8 top-level destinations
- 6-phase turn cycle

### Key Conclusions
- **Option count is thematically correct** — as General Secretary, having authority over all bureaus IS the point. The overwhelm is the game experience.
- **The scarcity of action points against the abundance creates strategic pressure** — this is good design
- **3 of 6 bureaus were broken** in the directive phase (P0 bug)
- **Triage assistance needed** — 207 options with no urgency indicators makes it hard to prioritize during crises

## Changes Made

### 1. Bureau Directive Target Selection Fix (P0)

**Problem:** `DirectivePhaseView.swift` passed `nil` for ALL target parameters when executing diplomatic, military, and state ministry directives. Actions requiring targets (e.g., "Request Country Briefing" with `targetType: .country`) always failed validation.

**Root Cause:** Three execution functions (`executeDiplomaticDirective`, `executeMilitaryDirective`, `executeStateMinistryDirective`) were implemented as pass-through stubs without target selection UI.

**Fix:** Complete rewrite of the directive execution flow in `DirectivePhaseView.swift`:

- **`executeDirective()`** now checks if the action needs a target via `directiveNeedsTarget()` before executing
- If a target is needed, shows the appropriate selection overlay instead of executing with `nil`
- **`finalizeDirective()`** accepts optional targets and routes to the correct service with actual selections

**5 new target selection overlays** (styled in Soviet-era gold/parchment aesthetic):

| Overlay | Target Type | Used By | Data Source |
|---------|-------------|---------|-------------|
| Country Selection | `ForeignCountry` | Diplomatic actions with `targetType: .country` | `game.foreignCountries` |
| Officer Selection | `GameCharacter` | Military actions with `targetType: .officer` | Military-track characters |
| Theater Selection | `TheaterCommand` | Military actions with `targetType: .theater` | `TheaterCommand.allCases` (5 theaters) |
| Ministry Selection | `MinistryDepartment` | State ministry actions with `targetType: .ministry` | `MinistryDepartment.allCases` (15 depts) |
| Official Selection | `GameCharacter` | State ministry actions with `targetType: .official` | State ministry-track characters |

Each overlay shows:
- Contextual information (bloc colors, disposition, success chance %, strategic focus)
- Bureau-consistent visual styling (gold headers, parchment background, monospaced fonts)
- Cancel button to back out

### 2. Crisis-Aware Urgency Triage System (P1)

**New File:** `Utilities/UrgencyAdvisor.swift` (148 lines)

Detects 9 crisis conditions from game state and maps them to relevant actions/bureaus:

| Crisis | Threshold | Relevant Stats | Relevant Bureaus |
|--------|-----------|---------------|-----------------|
| LOW STABILITY | stability < 30 | stability, popularSupport | Party, Security, State Ministry |
| RIVAL THREAT | rivalThreat > 65 | rivalThreat, network | Security |
| LOW FAVOR | patronFavor < 25 | patronFavor | Party |
| MILITARY UNREST | militaryLoyalty < 30 | militaryLoyalty | Military |
| ELITE DISSENT | eliteLoyalty < 30 | eliteLoyalty | Party, Security |
| LOW SUPPORT | popularSupport < 25 | popularSupport, stability | Party, State Ministry |
| POSITION AT RISK | standing < 20 | standing | Party |
| TREASURY DEPLETED | treasury < 15 | treasury | Economic, State Ministry |
| FOOD SHORTAGE | foodSupply < 20 | foodSupply | Economic, State Ministry |

**Integration Points:**

**Personal Action Phase (`PersonalActionView.swift`):**
- Crisis alert banner at top of screen showing active crises
- Action categories auto-sorted by crisis relevance (urgent categories float to top)
- Individual action cards tagged with crisis label when they address an active crisis

**Action Cards (`ActionCardView.swift`):**
- Red crisis label badge (e.g., "RIVAL THREAT") on relevant available actions
- Red-tinted border highlight on urgent action cards

**Directive Phase (`DirectivePhaseView.swift`, `BureauCommandCard.swift`):**
- Bureau cards show red crisis badge next to bureau name when the bureau is relevant to an active crisis

## Design Decisions

1. **Target selection uses modal overlays, not sheets** — maintains the Soviet-era visual consistency of the directive phase rather than breaking into iOS native sheet UI
2. **Urgency thresholds are conservative** — only flags genuine crises, not mild concerns. Avoids "everything is urgent" fatigue
3. **Category sorting preserves default order within non-urgent categories** — urgent categories float to top, but within the non-urgent group the original order is maintained
4. **Crisis detection is computed on each render** — no caching needed since the detection logic is lightweight (simple threshold checks on game properties)
