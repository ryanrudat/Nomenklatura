## Architectural Decisions

### Design Philosophy Locked In
**Brutalist Bureaucratic Theater** for daily UI + **Constructivist propaganda accents** for dramatic moments (achievements, succession, game-end). Soviet-flavored institutional language (Politburo, Five-Year Plan, Stakhanovite) is OK as game terms; real-world Soviet figure names (Stalin/Lenin/Brezhnev) are **never** used. Achievement names follow Tier-C style: descriptive, role-based, action-themed.

### Two Non-Negotiable Rules (saved to memory)
1. **The Chairman Sees Everything**: any UI showing "[REDACTED]" / "CLASSIFIED" must be tappable to reveal — built `RedactableText` / `RedactableSection` / `RedactionPattern` components. Locking information from the player breaks the power fantasy.
2. **AI Generates Narrative, Code Owns Mechanics**: newspapers, briefings, NPC dialogue, scenarios should be AI-generated for replayability. Action names, stats, UI labels stay coded. Phase 0 audit revealed scenarios were already AI-driven by Worker 6's prompt caching work; newspaper/samizdat AI conversion was explicitly deferred per user.

### 3.2 — Supply Chain Engine
- `SectorRecipe` struct + 32 recipes (one per existing SectorFocus). Highlights: Heavy/steel needs iron 8 + coal 4 → produces steel 6; Mining/iron_ore → iron 8; Energy/nuclear needs uranium 2 (atomic era).
- `RegionType.defaultEndowments` per-type baseline extraction capacities. Industrial → coal+iron. Coastal → oil+cotton+aluminum. Extractive → coal+iron+uranium+rareEarths.
- `SupplyChainResult` per-turn record: extractedByRegion, producedBySector, consumedBySector, shortfallBySector, deficitResources.
- `EconomySupplyChainEngine.processSupplyChain(game:)`:
  1. Extract: walk regions, scale endowments by region status (stable=100% / unrest=85% / crisis=50% / rebellion=25% / seceding=10% / seceded=0% / martial=70%).
  2. Apply recipes: bottleneck input ratio determines satisfaction.
  3. Persist updated reserves + result to Game.
- `Region.seedDefaultEndowmentsIfNeeded()` helper. Called in `createDefaultRegions()` after building all 7 regions.
- New step 7c in `EconomyService.processEconomy` calls the engine.

## Late-Session Addendum — Chairman Bypass Fixes (commit `7647bbd`)

Two Chairman-framing bugs surfaced after the main session wrap. Both were behavioral (not textual) so they slipped past Phase 1's text sweep.

### Bug 1: HistoricalSession redaction
**File:** `Models/HistoricalSession.swift:148-156`

`shouldRedact(forPosition:isOnCommittee:)` had four clearance tiers, with the top tier (`accessLevel >= 8`) always returning `true` regardless of position. Player-facing effect: opening the Sessions / Congress view as the Chairman showed `[REDACTED - INSUFFICIENT CLEARANCE]` on the highest-clearance historical sessions, which directly contradicts being the Chairman.

**Fix:** Added `if position >= 8 { return false }` short-circuit at the start of the function. The Chairman is the head of the Apparatus — there is no state document they lack clearance for. Lower-position scenarios (heir cultivation views, branching campaigns where the player is not yet at the top) keep the existing accessLevel-based redaction.

### Bug 2: AffinityGainCard claimed bureau access was locked
**File:** `Views/Outcome/OutcomeView.swift:265-272`

`AffinityGainCard.hasAccess` only returned `true` when the player either committed to a track (which Chairmen don't do — they're already at the top) OR accumulated 25 affinity per track. As a result, every "EXPERTISE GAINED" card after every decision claimed the Chairman was N points away from unlocking a bureau they already had universal access to. The progress bar at the bottom of the card was rendering with "0/25 — 25 more points to unlock Economic Planning access" while the player IS the Chairman.

**Fix:** Added `if game.currentPositionIndex >= 8 { return true }` short-circuit at the start of `hasAccess`. The card now shows the `+N` affinity gain badge + "Bureau access unlocked" checkmark for the Chairman. The broken progress bar / "X more points to unlock" hint sections are conditioned on `!hasAccess` and stop firing.

### Verification (Chairman-only redaction sites confirmed clean)
Audited the rest of the codebase for player-facing REDACTED text:
- `Views/Dossier/CharacterCardView.swift` — `redactedIntelSection` only renders when `hasIntelClearance == false`. For the Chairman: `playerClearance = min(currentPositionIndex + 1, 8) = 8`, max required clearance is 7, so `hasIntelClearance == true` always. Section never fires for Chairman.
- `Views/Components/RedactedTextView.swift` — legacy component (different from new `RedactableText`). No live call sites; effectively dead code that doesn't affect player view.
- No other view files actually display `[REDACTED]` text in player UI.

So the Chairman now sees full content everywhere with the model-layer fix above. No additional UI wrapping needed.
