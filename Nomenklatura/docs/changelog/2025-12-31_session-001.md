# Session Changelog: 2025-12-31 Session 001

## Overview
This session focused on implementing a document consequence system so that player decisions on desk documents have delayed future effects, and speeding up Turn 1 loading by pre-generating content during a preparation phase.

---

## 1. Document Consequence System

### Problem
Document decisions had immediate stat effects but no delayed consequences. Players could approve military operations, reject funding requests, or make personnel decisions without any future repercussions. The ConsequenceEngine only processed Law-based consequences.

### Solution
Extended the consequence system to track and process document-originated consequences.

### Files Modified

#### `Models/Law.swift`
- Added 9 new `ConsequenceType` cases for document decisions:
  - `bureaucraticBlowback` - Decision comes back to haunt you
  - `investigationOpened` - Your decision triggers scrutiny
  - `gratitude` - Someone remembers your help
  - `resentment` - Someone remembers your slight
  - `resourceShortage` - Approved spending causes problems
  - `operationalSuccess` - Approved operation succeeds
  - `operationalFailure` - Approved operation fails
  - `politicalFavor` - Decision earns you allies
  - `politicalEnmity` - Decision earns you enemies

- Updated `ScheduledConsequence` struct:
  - Added `relatedDocumentId: String?` to track source document
  - Added `relatedOptionId: String?` to track which option was selected
  - Added `isDocumentConsequence` computed property

#### `Models/Game.swift`
- Added `documentConsequencesData: Data?` for persistent storage
- Added `@Transient _documentConsequencesCache` for decoded cache
- Added `documentConsequences` computed property with encode/decode
- Added `scheduleDocumentConsequence(_ consequence:)` method
- Added `documentConsequencesDueThisTurn() -> [ScheduledConsequence]` method
- Added `markDocumentConsequenceTriggered(id:)` method

#### `Services/DocumentQueueService.swift`
- Added `scheduleDocumentConsequences(document:option:game:)` function
- Consequences only scheduled for impactful decisions (totalEffectMagnitude >= 10)
- Added 8 category-specific consequence generators:
  - `generateMilitaryConsequences()` - Operations may succeed/fail, military unrest
  - `generateSecurityConsequences()` - Investigations open, targets may retaliate
  - `generateEconomicDocConsequences()` - Resource shortages, economic effects
  - `generatePoliticalDocConsequences()` - Political favor/enmity, blowback
  - `generatePersonnelConsequences()` - Gratitude/resentment from appointments
  - `generateDiplomaticConsequences()` - International pressure, operational outcomes
  - `generateCrisisConsequences()` - Success/failure of crisis response
  - `generatePersonalConsequences()` - Personal favors create friends/enemies

#### `Services/ConsequenceEngine.swift`
- Updated `processConsequences(game:)` to handle both law and document consequences
- Added `applyDocumentConsequence(_:game:)` method
- Added `generateDocumentConsequenceNarrative(_:game:)` with themed text for each type
- Updated switch statements for exhaustive handling of new consequence types
- Made `ProcessedConsequence.law` property optional for document consequences
- Updated `createConsequenceEvent()` to handle optional law and use document ID as fallback

## 2. Turn 1 Loading Speed Improvement

### Problem
The "Preparation Briefing" on Turn 1 was slow because AI content generation only started when DeskView appeared, after the game was already visible. Players had to wait watching a loading screen.

### Solution
Added a dedicated preparation phase between faction selection and gameplay that pre-generates all Turn 1 content before showing the game.

### Files Modified

#### `ContentView.swift`
- Added new `GameSetupState.preparing(campaignId:factionId:)` case
- Updated faction selection to transition to `.preparing` instead of `.playing`
- Removed `setupState = .playing` from `startNewGame()` (now managed by preparation view)

- Created `GamePreparationView` with:
  - Themed loading screen with star icon and progress bar
  - 4-phase progress tracking:
    1. Creating your political dossier...
    2. Preparing government documents...
    3. Briefing the General Secretary...
    4. Setting up your office...
  - Animated progress bar with percentage
  - Phase indicator dots
  - Flavor text: "The apparatus awaits your orders."

- Preparation flow:
  1. Shows loading screen immediately on faction selection
  2. Creates the game (calls `onCreateGame`)
  3. Generates documents via `DocumentQueueService`
  4. Starts scenario/briefing generation via `ScenarioManager`
  5. Waits for completion (max 15 second timeout)
  6. Transitions to gameplay when ready

## Technical Notes

### Consequence Timing
- Base delay: 2-5 turns in the future
- Crisis consequences come 1 turn faster
- Consequence magnitude affects stat effect severity
- Consequences fire during `endTurnUpdates()` via ConsequenceEngine

### Document Consequence Logic
- Military: 50% success/failure on approved operations
- Security: Investigations can expose targets who may retaliate
- Economic: Spending decisions may cause resource shortages
- Political: Decisions create favor or enmity
- Personnel: Appointments create gratitude, rejections create resentment
- Diplomatic: International reactions and operational outcomes
- Crisis: Active response can succeed or need more resources
- Personal: Helping creates friends, refusing creates enemies

### Pre-generation Benefits
- Turn 1 now appears instantly with all content ready
- Progress feedback keeps players informed during load
- 15-second timeout prevents infinite loading
- Content cached in ScenarioManager for immediate use
