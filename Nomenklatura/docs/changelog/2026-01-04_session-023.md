### 3. Player-Initiated Notes (Intelligence Alert System)

Converted auto-saved journal entries to dismissable alerts requiring player decision.

**New Model: `IntelligenceAlert`**
```swift
struct IntelligenceAlert: Codable, Identifiable, Sendable {
    var id: UUID
    var turnDiscovered: Int
    var category: JournalCategory
    var title: String
    var content: String
    var relatedCharacterId: String?
    var relatedCharacterName: String?
    var relatedFactionId: String?
    var relatedLawId: String?
    var importance: Int
    var createdAt: Date
    var contentHash: String  // SHA256 hash for deduplication
}
```

**Deduplication System:**
- Each alert generates a `contentHash` using SHA256 of title + content + characterId
- Three-way duplicate check before creating alerts:
  1. Check pending alerts
  2. Check dismissed alert hashes
  3. Check saved journal entries
- Player can only save intelligence once - no redundant saves possible

**New Files Created:**
- `Models/IntelligenceAlert.swift` - Alert model with hash generation and Game extensions
- `Services/IntelligenceAlertService.swift` - Alert management with deduplication
- `Views/Components/IntelligenceAlertView.swift` - Modal UI with Save/Dismiss buttons

**Game Model Extensions:**
- Added `pendingAlertsData: Data?` for storing pending alerts

- Added computed properties: `pendingAlerts`, `dismissedAlertHashes`, `savedAlertHashes`

### Design Principles Applied

1. **Player Agency** - Notes only saved when player explicitly chooses
2. **No Redundancy** - SHA256 hashing prevents duplicate intelligence saves
3. **Layered Visibility** - Network stat determines what player can see
4. **Organic World** - NPCs have lives, relationships, and autonomous actions
5. **Family Matters** - Deep family connections add narrative weight
6. **Chronological Memory** - Player can track NPC actions over time

## Architecture Decisions

### Why SHA256 for Deduplication?
- Consistent hash regardless of when alert is generated
- Fast comparison via Set membership
- Survives app restarts (stored in Data field)
- 16-character prefix sufficient for practical uniqueness

### Why Route Through Alert System?
- Respects player agency - they choose what to remember
- Prevents journal bloat from auto-generated entries
- Creates intentional note-taking gameplay
- Mirrors real intelligence analyst workflow

### Why Separate NPCHistoryEvent from NPCMemory?
- `NPCMemory` is AI-internal (not shown to player)
- `NPCHistoryEvent` is player-visible (what player observes)
- Different purposes, different data structures
- Player sees curated timeline, AI has full context
