## The Two Bugs

### Bug 1 — HistoricalSession redaction (commit `7647bbd`)
**File:** `Models/HistoricalSession.swift:148-156`

`shouldRedact(forPosition:isOnCommittee:)` had four clearance tiers, with the top tier (`accessLevel >= 8`) always returning `true` regardless of position. Player-facing effect: opening the Sessions / Congress view as the Chairman showed `[REDACTED - INSUFFICIENT CLEARANCE]` on the highest-clearance historical sessions — directly contradicting being the Chairman.

**Fix:** Added `if position >= 8 { return false }` short-circuit at the start of the function. Lower-position scenarios (heir cultivation views, branching campaigns) keep the existing accessLevel-based redaction.

### Bug 2 — AffinityGainCard claimed bureau access was locked (commit `7647bbd`)
**File:** `Views/Outcome/OutcomeView.swift:265-272`

`AffinityGainCard.hasAccess` only returned `true` when the player either committed to a track (which Chairmen don't do — they're already at the top) OR accumulated 25 affinity per track. As a result, every EXPERTISE GAINED card after every decision claimed the Chairman was N points away from unlocking a bureau they already had universal access to. The progress bar at the bottom of the card rendered "0/25 — 25 more points to unlock Economic Planning access" while the player IS the Chairman.

**Fix:** Added `if game.currentPositionIndex >= 8 { return true }` short-circuit at the start of `hasAccess`. The card now shows the `+N` affinity gain badge + "Bureau access unlocked" checkmark for the Chairman. The broken progress bar / "X more points to unlock" hint sections are conditioned on `!hasAccess` and stop firing.

## The Pattern (locked in)

> Whenever a UI feature gates content behind a clearance/access check that compares against the player's current position, **explicitly short-circuit at `position >= 8` to grant access**. If you find yourself adding a clearance check, ask whether a Chairman would ever encounter the failure case — if not, add the bypass at the same time.
